# Upstream workarounds

Every place where Pikibun works around a dependency's bug or gap, with where the workaround lives, what tracks it upstream and when to remove it. Add a row when adding a workaround, and remove it with the workaround. `tests/upstream-workarounds.test.ts` checks that each patch `scripts/nsh-web-fixes.mjs` applies to Native Shell's built web runtime is listed here.

Native Shell (NSH) is pinned in `scripts/nsh.mjs`: `NSH_VERSION`, the commit it was built from (`NSH_COMMIT`) and the SHA-256 of each release asset it downloads (`NSH_ASSET_SHA256`): each platform's CLI, which holds that platform's own runtime, and since 0.5 the other runtimes, which are components of their own (`NSH_COMPONENTS`: web, Android, iOS). `nsh` would add a missing component itself, checked only against the `.sha256` the same release publishes, so `scripts/nsh.mjs` adds the one a command's `--target` needs first (`--component <name>` adds one alone). A download is checked against the pinned digests, never against a checksum the same release publishes, so a replaced asset fails the build. Upgrading NSH means updating all three, then checking each row below against the new release.

## Native Shell

| Workaround | Where | Upstream | Remove when |
|---|---|---|---|
| **Text widths on the web** (`MEASURE_TEXT`, `PATCHED_MEASURE_TEXT`, `DRAWN_WIDTH`): NSH (0.4 and 0.5) lays text out with the canvas's `measureText` widths and draws it as page text, so where a browser's canvas measures a font otherwise, each run overlaps the next (#250). The build measures such a font as the page draws it. 0.5 measures numeric text in the page, but not other text. | `scripts/nsh-web-fixes.mjs`, `tests/nsh-web-fixes.test.ts` | None filed yet: file one on longbridge/nsh and link it here | NSH measures text as the page draws it. The build fails once `measure_text` changes. |
| **Inline scripts in the page's policy**: NSH's web loader inserts an import map whose content changes on every load, and `blob:` modules, which no hash can allow. 0.5 inserts it before the app's first module (longbridge/nsh#1118), but still inline. The page's CSP keeps `'unsafe-inline'` for scripts; see [Content Security Policy](security-rationale.md#content-security-policy). | `apps/server/src/static.ts`, `tests/static.test.ts`, `tests/transcript-html.test.ts` | Needs nonce support in NSH's loader; none filed yet | NSH's loader takes a nonce for the scripts it inserts. |
| **App Store builds**: NSH's prebuilt iPhone runner (0.4's, and 0.5's `ios` component) was linked with the iOS 18.5 SDK, which App Store Connect no longer takes, and `nsh package` writes none of the build keys it requires. The release builds the runner from NSH's source (`NSH_RUNTIME`), adds the keys and signs again. | `.github/workflows/release-app.yml` | None filed | An NSH release links a current SDK and writes the keys. |
| **Native sign-in in the system browser**: NSH has no system authentication session (longbridge/nsh#1065, closed as not planned). Since 0.5 the app claims `pikibun://` (`nsh.json` `schemes`), so native sign-in opens GitHub's page in the system browser (`openUrl`) and the server hands the sign-in back as `pikibun://auth?code=…&state=…`, which the app finishes (`UrlScheme.on("open")`) only when its state is this attempt's, with its PKCE verifier. Anyone can open a `pikibun://` link: one with another state is refused and leaves the attempt waiting. **Sign in here instead** still runs the page in the app's web view, handed back on `/api/auth/native/done`, for a desktop that can't open the app from the browser, and for `pnpm test:client-macos --github`. | `apps/server/src/authority/auth.ts`, `apps/nsh/src/lib/auth.ts`, `apps/nsh/src/screens/SignIn.tsx` | [longbridge/nsh#1065](https://github.com/longbridge/nsh/issues/1065) | NSH has an authentication session, or the in-app fallback is no longer needed. |
| **Sign-ins in a plain file**: native sign-ins are kept in NSH's `Storage`, not the Keychain or Keystore. | `apps/nsh/src/lib/auth.ts` | [longbridge/nsh#1061](https://github.com/longbridge/nsh/issues/1061) | NSH stores secrets in the platform's keychain. |
| **A held finger's lift after a context menu** (`rowPress`): NSH 0.4's `ContextMenu` opened on a finger held on its trigger but only watched the finger, and the platforms reported its lift as a press of the trigger. A session's row opened the session under its menu, and a workspace's folded. 0.5 cancels the trigger's press once a held finger opens its menu (longbridge/nsh#1415), but rows that slide open their menu from their own long press (`detached`, the row below), which that doesn't cover. `RowMenu` notes the menu a held finger opened, and `rowPress` drops the one press after it. The menu's closing, or its row's unmounting, forgets it, so a lift no platform reported costs at most one tap. NSH's headless `longPress` sends no press, so the tests send the lift's press themselves. | `apps/nsh/src/ui.tsx`, `apps/nsh/tests/menus.test.tsx` | [longbridge/nsh#1415](https://github.com/longbridge/nsh/pull/1415) for a `ContextMenu`'s own trigger | Checked on phones that a pressable view's lift after its own long press is no press, or the rows below no longer open their menu themselves. |
| **A context menu's trigger takes every touch** (`RowMenu`'s `detached`): on touch screens NSH 0.4's `ContextMenu` takes every touch on its trigger, even disabled, so a view in it that pans (`SwipeRow`) never hears its drags. Where rows slide (`swipesRows`), a session's row isn't the trigger: the row opens its menu from its own long press, and the menu sits beside it, opened through `open`; while open it counts as a held finger's menu for `rowPress` (the row above). The desktops keep the menu around the row. Not checked against 0.5 on phones. | `apps/nsh/src/ui.tsx`, `apps/nsh/src/screens/SessionList.tsx`, `apps/nsh/tests/swipe.test.tsx` | None filed: file one on longbridge/nsh and link it here | A pan inside a `ContextMenu`'s trigger takes its drags, with the held finger still opening the menu. |
| **No long press on a base button**: `nsh/base`'s `Button` has no `onLongPress` (0.5 neither), and a view around it hears none through it. Where rows slide, a session's row is a pressable `View` instead (`role="button"`, its selection in `accessibilityState`), so its own long press can open its menu. | `apps/nsh/src/screens/SessionList.tsx` | None filed | `Button` takes `onLongPress`, or the menu no longer needs the row's own (the row above). |
| **Release speed in headless drags**: the headless engine drags at 600 points a second and reports that speed at the release even after a pause, so a slowly let-go swipe can't be played there. The rule for where a swiped row rests (`swipeRest`) is tested on its own, and the app's tests swipe with flicks. | `apps/nsh/tests/swipe.test.tsx` | None filed | Headless drags report the speed at their release. |
| **An update's download through the local proxy**: NSH's `fetch` (0.5) follows only the app process's own proxy variables on Windows and Linux (ureq) and only the system's proxy settings on macOS (`NSURLSession`), and takes no proxy of its own, so a Windows or GNOME proxy setting, or a login shell's `https_proxy`, never carried the desktop app's update. The app finds that proxy itself and downloads the package with curl through it. | `apps/nsh/src/lib/update-proxy.ts`, `apps/nsh/src/lib/app-update.ts`, `tests/app-update-proxy.test.ts` | None filed: file one on longbridge/nsh and link it here | NSH's `fetch` follows the system's proxy settings on every desktop, and a shell's variables, or takes a proxy. |
| **cmd.exe's own messages in another language** (`windows-cmd.ts`): NSH's `process.spawn` and `process.run` (0.5) read a child's stdout and stderr as UTF-8 only, and its `TextDecoder` has no legacy code pages. cmd.exe writes its own messages, such as "'pikibun' is not recognized as an internal or external command", in Windows' display language and the console's code page, so on a Chinese, Japanese or Korean Windows (GBK, Shift-JIS, UHC, ...) they arrived as U+FFFD. The English pattern that tells a missing command never matched either, so the owner saw mojibake instead of the offer to install it. Each line the app runs Pikibun's command or npm through starts with `chcp 65001 >nul 2>nul &`, which switches the child's own hidden console to UTF-8 (and does nothing, silently, without one). It then asks `where /q` for the program and runs `exit 9009`, cmd's own code for a missing command, when it isn't there, whatever the language. Output that still holds U+FFFD gives way to the exit code (`lastLines`). `tests/windows-cmd.test.ts` runs the lines through a real cmd.exe in CI's Windows job. | `apps/nsh/src/lib/windows-cmd.ts`, `apps/nsh/src/lib/pikibun-command.ts`, `tests/windows-cmd.test.ts` | None filed: file one on longbridge/nsh and link it here | NSH decodes a child's output in the system's code page, or takes an encoding; the `where` check can stay, as it is what tells a missing command in any language. |
| **`CryptoKey` type**: NSH (0.4 and 0.5) declares `CryptoKey` only as a value. | `apps/nsh/src/globals.d.ts` | None filed | NSH declares the type. |
| **A test harness that writes files** (`tests/harness/home`): since 0.5 an app imports only files inside its directory, the nearest one up with an `nsh.json`. The harnesses build with the app's `nsh.json`, but the attach test's writes the files it hands over to the home folder, which the app may only read, so it has an `nsh.json` of its own, and imports nothing that imports a file: `Logo`, the app's only one, is in `src/logo.tsx`, apart from the kit. | `apps/nsh/tests/harness/home/nsh.json`, `apps/nsh/src/logo.tsx` | None filed | Headless tests can stage files, or grant an entry more than its app's `nsh.json`. |
