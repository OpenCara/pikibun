# Upstream workarounds

Every place where Pikibun works around a dependency's bug or gap, with where the workaround lives, what tracks it upstream and when to remove it. Add a row when adding a workaround, and remove it with the workaround. `tests/upstream-workarounds.test.ts` checks that each patch `scripts/nsh-web-fixes.mjs` applies to Native Shell's built web runtime is listed here.

Native Shell (NSH) is pinned in `scripts/nsh.mjs`: `NSH_VERSION`, the commit it was built from (`NSH_COMMIT`) and the SHA-256 of each platform's release asset (`NSH_ASSET_SHA256`). A download is checked against those digests, never against a checksum the same release publishes, so a replaced asset fails the build. Upgrading NSH means updating all three, then checking each row below against the new release.

## Native Shell

| Workaround | Where | Upstream | Remove when |
|---|---|---|---|
| **Early import map** (`BEFORE_BOOTSTRAP`, `LATE_MAP`, `EARLY_MAP`): NSH 0.4's web runtime starts an app realm before it inserts the realm's import map, so the realm's first imports fail in some browsers. The build inserts the map before the realm starts, and skips the late one. | `scripts/nsh-web-fixes.mjs` (`fixWebSite`), `tests/nsh-web-fixes.test.ts` | [longbridge/nsh#1118](https://github.com/longbridge/nsh/issues/1118) | NSH starts realms after their import map. The build fails, naming this issue, once the patched code is gone. |
| **Text widths on the web** (`MEASURE_TEXT`, `PATCHED_MEASURE_TEXT`, `DRAWN_WIDTH`): NSH 0.4 lays text out with the canvas's `measureText` widths and draws it as page text, so where a browser's canvas measures a font otherwise, each run overlaps the next (#250). The build measures such a font as the page draws it. | `scripts/nsh-web-fixes.mjs`, `tests/nsh-web-fixes.test.ts` | None filed yet: file one on longbridge/nsh and link it here | NSH measures text as the page draws it. The build fails once `measure_text` changes. |
| **Inline scripts in the page's policy**: NSH's web loader inserts an import map whose content changes on every load, and `blob:` modules, which no hash can allow. The page's CSP keeps `'unsafe-inline'` for scripts; see [Content Security Policy](security-rationale.md#content-security-policy). | `apps/server/src/static.ts`, `tests/static.test.ts`, `tests/transcript-html.test.ts` | Needs nonce support in NSH's loader; none filed yet | NSH's loader takes a nonce for the scripts it inserts. |
| **No `lifecycle` on the web**: NSH 0.4's web runtime has no `lifecycle` (its import is undefined), so a stand-in counts the page as always active. | `apps/nsh/src/lib/lifecycle.ts` | None filed | NSH's web runtime has `lifecycle`. |
| **App Store builds**: NSH 0.4's prebuilt iPhone runner was linked with an SDK App Store Connect no longer takes, and `nsh package` writes none of the build keys it requires. The release builds the runner from NSH's source (`NSH_RUNTIME`), adds the keys and signs again. | `.github/workflows/release-app.yml` | None filed | An NSH release links a current SDK and writes the keys. |
| **Native sign-in page**: NSH has neither a system authentication session nor deep links, so native sign-in runs GitHub's page in the app's web view, and the server hands the sign-in back on a page of its own (`/api/auth/native/done`). | `apps/server/src/authority/auth.ts`, `apps/nsh/src/lib/auth.ts` | [longbridge/nsh#1065](https://github.com/longbridge/nsh/issues/1065) | NSH has an authentication session or deep links. |
| **Sign-ins in a plain file**: native sign-ins are kept in NSH's `Storage`, not the Keychain or Keystore. | `apps/nsh/src/lib/auth.ts` | [longbridge/nsh#1061](https://github.com/longbridge/nsh/issues/1061) | NSH stores secrets in the platform's keychain. |
| **A held finger's lift after a context menu** (`rowPress`): NSH 0.4's `ContextMenu` opens on a finger held on its trigger but only watches the finger, and the platforms report its lift as a press of the trigger, which hears no long presses of its own. A session's row opened the session under its menu, and a workspace's folded. `RowMenu` notes the menu a held finger opened, and `rowPress` drops the one press after it. The menu's closing, or its row's unmounting, forgets it, so a lift no platform reported costs at most one tap. NSH's headless `longPress` sends no press, so the tests send the lift's press themselves. | `apps/nsh/src/ui.tsx`, `apps/nsh/tests/menus.test.tsx` | None filed: file one on longbridge/nsh and link it here | NSH's `ContextMenu` cancels its trigger's press once a held finger opened it. |
| **`CryptoKey` type**: NSH 0.4 declares `CryptoKey` only as a value. | `apps/nsh/src/globals.d.ts` | None filed | NSH declares the type. |
| **Zero window sizes in tests**: after `setColorScheme`, the headless engine reports the window as 0×0, so the layout ignores zero sizes. | `apps/nsh/src/Root.tsx` | None filed | The headless engine keeps the window's size. |
| **Scroll view order in tests**: headless `texts()` lists a scroll view's content in view-tree order, not screen order. | `apps/nsh/tests` | Fixed in [longbridge/nsh#1105](https://github.com/longbridge/nsh/pull/1105), after 0.4 | The pinned NSH includes #1105. |
