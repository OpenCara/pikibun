# Upstream workarounds

Every place where Pikibun works around a dependency's bug or gap, with where the workaround lives, what tracks it upstream and when to remove it. Add a row when adding a workaround, and remove it with the workaround. `tests/upstream-workarounds.test.ts` checks that each patch `scripts/nsh-web-fixes.mjs` applies to Native Shell's built web runtime is listed here.

Native Shell (NSH) is pinned in `scripts/nsh.mjs`: `NSH_VERSION`, the commit it was built from (`NSH_COMMIT`) and the SHA-256 of each release asset it downloads (`NSH_ASSET_SHA256`): each platform's CLI, which holds that platform's own runtime, and since 0.5 the other runtimes, which are components of their own (`NSH_COMPONENTS`: web, Android, iOS, and the terminal host, one archive per platform, `NSH_TUI_HOSTS`, which [`@pikibun/tui`](tui.md) also ships). `nsh` would add a missing component itself, checked only against the `.sha256` the same release publishes, so `scripts/nsh.mjs` adds the one a command's `--target` needs first (`--component <name>` adds one alone). A download is checked against the pinned digests, never against a checksum the same release publishes, so a replaced asset fails the build. Upgrading NSH means updating all three, then checking each row below against the new release.

## Native Shell

| Workaround | Where | Upstream | Remove when |
|---|---|---|---|
| **Text widths on the web** (`MEASURE_TEXT`, `PATCHED_MEASURE_TEXT`, `DRAWN_WIDTH`): NSH (0.4 to 0.7) lays text out with the canvas's `measureText` widths and draws it as page text, so where a browser's canvas measures a font otherwise, each run overlaps the next (#250). The build measures such a font as the page draws it. 0.5 measures numeric text in the page, but not other text, and 0.6 and 0.7 still don't (0.6 changed only the minifier's names in `measure_text`; 0.7's is the same, and its canvas `measureText` adds only the font's ascent and descent). | `scripts/nsh-web-fixes.mjs`, `tests/nsh-web-fixes.test.ts` | None filed yet: file one on longbridge/nsh and link it here | NSH measures text as the page draws it. The build fails once `measure_text` changes. |
| **QR codes and scanning**: NSH draws no QR codes and has no camera. **Sign in an app** (Settings → Profile → Signed-in apps) shows its `pikibun://auth/code` link as a QR code that the app encodes itself, byte mode at error correction level M, the smallest version 1 to 40 that holds the link, and the mask with the lowest penalty, as ISO/IEC 18004 describes and Project Nayuki's QR Code generator (MIT) implements, drawn on `Canvas` black on white with a quiet zone of 4 modules in every theme. `tests/qr.test.ts` pins its output, module for module, to python-qrcode's for the same text and mask. A phone scans it with the system's camera, which opens the link in the app; the app reads no QR codes itself, and a computer pastes the link instead. | `apps/nsh/src/lib/qr.ts`, `apps/nsh/src/components/QrCode.tsx`, `tests/qr.test.ts` | None filed | NSH draws QR codes, or reads them with the camera. |
| **Sign-ins in a plain file**: native sign-ins are kept in NSH's `Storage`, not the Keychain or Keystore. | `apps/nsh/src/lib/auth.ts` | [longbridge/nsh#1061](https://github.com/longbridge/nsh/issues/1061) | NSH stores secrets in the platform's keychain. |
| **A held finger's lift after a context menu** (`rowPress`): NSH 0.4's `ContextMenu` opened on a finger held on its trigger but only watched the finger, and the platforms reported its lift as a press of the trigger. A session's row opened the session under its menu, and a workspace's folded. 0.5 cancels the trigger's press once a held finger opens its menu (longbridge/nsh#1415), but rows that slide open their menu from their own long press (`detached`, the row below), which that doesn't cover. `RowMenu` notes the menu a held finger opened, and `rowPress` drops the one press after it. The menu's closing, or its row's unmounting, forgets it, so a lift no platform reported costs at most one tap. NSH's headless `longPress` sends no press, so the tests send the lift's press themselves. | `apps/nsh/src/ui.tsx`, `apps/nsh/tests/menus.test.tsx` | [longbridge/nsh#1415](https://github.com/longbridge/nsh/pull/1415) for a `ContextMenu`'s own trigger | Checked on phones that a pressable view's lift after its own long press is no press, or the rows below no longer open their menu themselves. |
| **A context menu's trigger takes every touch** (`RowMenu`'s `detached`): on touch screens NSH 0.4's `ContextMenu` takes every touch on its trigger, even disabled, so a view in it that pans (`SwipeRow`) never hears its drags. Where rows slide (`swipesRows`), a session's row isn't the trigger: the row opens its menu from its own long press, and the menu sits beside it, opened through `open`; while open it counts as a held finger's menu for `rowPress` (the row above). The desktops keep the menu around the row. Not checked against 0.5 on phones. | `apps/nsh/src/ui.tsx`, `apps/nsh/src/screens/SessionList.tsx`, `apps/nsh/tests/swipe.test.tsx` | None filed: file one on longbridge/nsh and link it here | A pan inside a `ContextMenu`'s trigger takes its drags, with the held finger still opening the menu. |
| **No long press on a base button**: `nsh/base`'s `Button` has no `onLongPress` (0.5 and 0.6 neither), and a view around it hears none through it. Where rows slide, a session's row is a pressable `View` instead (`role="button"`, its selection in `accessibilityState`), so its own long press can open its menu. | `apps/nsh/src/screens/SessionList.tsx` | None filed | `Button` takes `onLongPress`, or the menu no longer needs the row's own (the row above). |
| **Release speed in headless drags**: the headless engine drags at 600 points a second and reports that speed at the release even after a pause, so a slowly let-go swipe can't be played there. The rule for where a swiped row rests (`swipeRest`) is tested on its own, and the app's tests swipe with flicks. | `apps/nsh/tests/swipe.test.tsx` | None filed | Headless drags report the speed at their release. |
| **An update's download through the local proxy**: NSH's `fetch` (0.5) follows only the app process's own proxy variables on Windows and Linux (ureq) and only the system's proxy settings on macOS (`NSURLSession`), and takes no proxy of its own, so a Windows or GNOME proxy setting, or a login shell's `https_proxy`, never carried the desktop app's update. The app finds that proxy itself and downloads the package with curl through it. | `apps/nsh/src/lib/update-proxy.ts`, `apps/nsh/src/lib/app-update.ts`, `tests/app-update-proxy.test.ts` | None filed: file one on longbridge/nsh and link it here | NSH's `fetch` follows the system's proxy settings on every desktop, and a shell's variables, or takes a proxy. |
| **cmd.exe's own messages in another language** (`windows-cmd.ts`): NSH's `process.spawn` and `process.run` (0.5) read a child's stdout and stderr as UTF-8 only, and its `TextDecoder` has no legacy code pages. cmd.exe writes its own messages, such as "'pikibun' is not recognized as an internal or external command", in Windows' display language and the console's code page, so on a Chinese, Japanese or Korean Windows (GBK, Shift-JIS, UHC, ...) they arrived as U+FFFD. The English pattern that tells a missing command never matched either, so the owner saw mojibake instead of the offer to install it. Each line the app runs Pikibun's command or npm through starts with `chcp 65001 >nul 2>nul &`, which switches the child's own hidden console to UTF-8 (and does nothing, silently, without one). It then asks `where /q` for the program and runs `exit 9009`, cmd's own code for a missing command, when it isn't there, whatever the language. Output that still holds U+FFFD gives way to the exit code (`lastLines`). `tests/windows-cmd.test.ts` runs the lines through a real cmd.exe in CI's Windows job. | `apps/nsh/src/lib/windows-cmd.ts`, `apps/nsh/src/lib/pikibun-command.ts`, `tests/windows-cmd.test.ts` | None filed: file one on longbridge/nsh and link it here | NSH decodes a child's output in the system's code page, or takes an encoding; the `where` check can stay, as it is what tells a missing command in any language. |
| **The host's environment, name by name** (`agentSocketImport`): NSH (0.5) gives a child `PATH`, `HOME`, `TMPDIR`, `LANG`, `LC_*` and a few more, plus the names `capabilities.process.env` lists, matched exactly, and an app without `capabilities` may start no process at all. So the host the desktop app starts never had what only the GUI session sets, above all `SSH_AUTH_SOCK` (launchd's on macOS, the desktop keyring's on Linux), and the owner's on-host sessions couldn't reach their ssh agent. `nsh.json` names `SSH_AUTH_SOCK` and `SSH_AGENT_PID`. Where neither NSH nor the shell profile set one, the login shell's command looks the socket up itself (`launchctl getenv SSH_AUTH_SOCK`, `systemctl --user show-environment`) and exports it only when it is an absolute path. Any other GUI-session variable still needs its name added. | `apps/nsh/nsh.json`, `apps/nsh/src/lib/agent-socket.ts`, `apps/nsh/src/lib/pikibun-command.ts`, `tests/agent-socket.test.ts` | None filed: the `longbridge` organization restricts OAuth apps, so file it by hand (the request is in #322's description) and link it here | NSH lets a child inherit the host's whole environment, or names by prefix; then grant that and drop the lookup. |
| **A Rust module for one target only** (`NSH_TARGET_MODULES`): pushed notifications on iPhone need `nsh-extra`'s `push` (0.7), a Rust nshm. NSH (0.7) lists an app's modules in `nsh.json` `"dependencies"` for every target at once, and an app with a Rust module no longer packages from the prebuilt runtimes: each target's runner is built from source with the Rust toolchain, the web's (to wasm), the six terminal hosts' and every desktop's too, which the image, CI and the release pin by SHA-256 and build without Rust. So `nsh.json` lists no module. `scripts/nsh.mjs` adds `nsh-extra` (the pinned NSH's own version, its crate checked against a pinned SHA-256, locked in an `nsh.lock` it writes) to `nsh.json` only while a command runs with `--target ios`, then puts the file back. The app reaches the module with a dynamic `import()` of its specifier, which the bundle leaves to the runtime: it resolves where the runner links the module and is refused elsewhere, where the app goes without pushes. Its declarations (`.nsh/types/nsh-extra.d.ts`) exist only in such a build, so `src/lib/push.ts` declares the part it uses, and headless tests, whose runner doesn't link the module, stand in for it at that seam (`configurePush`) instead of with `app.fake`. | `scripts/nsh.mjs`, `apps/nsh/src/lib/push.ts`, `apps/nsh/tests/harness/push.tsx`, `tests/nsh-download.test.ts` | None filed: file one on longbridge/nsh and link it here | NSH takes dependencies per target, or links a Rust module's targets from prebuilt parts; then list `nsh-extra` in `nsh.json` and import it statically. |
| **No tooltips in a terminal** (`IconButton`): in NSH 0.7's terminal host (0.7.2 too), a button with a `tooltip` that is gone once pressed (the main toolbar's **New session** over a session, which the home replaces) leaves its tooltip holding the next click, which then does nothing. An icon button has no tooltip where the app runs in a terminal (`inTerminal`), where hovering for one is rare anyway; its label still reads in the accessibility tree. `tests/terminal.test.tsx` opens Profile right after **New session**, under `--target tui` in CI. | `apps/nsh/src/ui.tsx`, `apps/nsh/tests/terminal.test.tsx` | None filed: file one on longbridge/nsh and link it here | A terminal's tooltip goes with its button, or a click outside it passes through. |
| **`CryptoKey` type**: NSH (0.4 to 0.7) declares `CryptoKey` only as a value. | `apps/nsh/src/globals.d.ts` | None filed | NSH declares the type. |
| **A test harness that writes files** (`tests/harness/home`): since 0.5 an app imports only files inside its directory, the nearest one up with an `nsh.json`. The harnesses build with the app's `nsh.json`, but the attach test's writes the files it hands over to the home folder, which the app may only read, so it has an `nsh.json` of its own, and imports nothing that imports a file: `Logo`, the app's only one, is in `src/logo.tsx`, apart from the kit. | `apps/nsh/tests/harness/home/nsh.json`, `apps/nsh/src/logo.tsx` | None filed | Headless tests can stage files, or grant an entry more than its app's `nsh.json`. |
