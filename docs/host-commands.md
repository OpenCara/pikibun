# Host commands

Host commands run **outside the sandbox, as the connector's OS user**: the tools of the workspace's [extensions](extensions.md), and every command of a session that runs on the host itself (a host without the sandbox, or a member's [session on the host](hosts.md#host-admins-and-host-command-grants)). They can read and change host files and credentials, use the network, and run without CPU, memory, process or disk limits. The agent can change the worktree's files and Git configuration, so builds, package scripts and Git hooks there can run its code on the host, even for a command as harmless-looking as `git status`. Approve a host command only if you would run it yourself in that directory.

Each one needs the approval of the **host's owner**, or of a member they [granted host commands](hosts.md#host-admins-and-host-command-grants), whoever sent the message. Under the session owner's **Auto-approve** they run without asking only on the owner's own host, or for a member granted automatic host commands there.

There is no `host_bash` any more (#163): sessions no longer ask to run a shell command on the host from a sandboxed session. When a task needs an SDK the sandbox lacks, add it to the host so the sandbox sees it, use one of [Pikibun's built-in extensions](extensions.md#pikibuns-built-in-extensions-gh-glab-and-az), or run the session on the host. Approvals of `host_bash` commands from before stay readable.
