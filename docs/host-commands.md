# Host commands

Host commands run **outside the sandbox, as the connector's OS user**: the tools of the workspace's [extensions](extensions.md) (except installed ones in a sandboxed session on a Linux host, which run in the sandbox), and every command of a session that runs on the host itself (a host without the sandbox, or a member's [session on the host](hosts.md#host-admins-and-host-command-grants)). They can read and change host files and credentials, use the network, and run without CPU, memory, process or disk limits. The agent can change the worktree's files and Git configuration, so builds, package scripts and Git hooks there can run its code on the host, even for a command as harmless-looking as `git status`. Grant host commands only to people you would let run commands in that directory yourself.

They run only in sessions of the **host's owner**, or of a member they [granted host commands](hosts.md#host-admins-and-host-command-grants), for messages of theirs, and never in a **Read only** message. Everyone else's are refused; nobody is asked. The host's owner can let every session run its workspace's extension tools (**Settings → Hosts →** the host **→ Extensions**).

There is no `host_bash` any more (#163): sessions no longer ask to run a shell command on the host from a sandboxed session. When a task needs an SDK the sandbox lacks, add it to the host so the sandbox sees it, use one of [Pikibun's built-in extensions](extensions.md#pikibuns-built-in-extensions-gh-glab-and-az), or run the session on the host. Approvals of `host_bash` commands from before stay readable.
