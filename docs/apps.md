# iPhone, iPad, Mac and Windows apps

- **iPhone and iPad** ([`apps/mobile`](../apps/mobile/README.md), Expo): your sessions grouped by workspace with their status; a session opens live with its transcript, queue, pending approvals to decide, and the chat box for shared messages and side asks; new sessions start from the app. It isn't on the App Store or TestFlight yet: build it from source as a development build.
- **macOS** ([`apps/desktop`](../apps/desktop/README.md), Electron): Pikibun in its own windows, as on the web (a session can open in a window of its own), plus **This Mac**, which runs the `pikibun` connector on the Mac without a terminal, for one server or several at once, each with its own host and pairing. Its settings are in the web app: **Settings → This Mac**, shown only in the app, lists the servers and their hosts, pairs the Mac with the server it belongs to in one click (as does **Settings → Hosts → Pair a host**), and runs Pikibun on the Mac; other servers pair from their own Settings, or with a pairing ID and code in the app. The primary server shares the command-line connector's state, so a Mac paired with `pikibun connect` is adopted as is, and only one of the two can run at a time. Each server's host chooses its **Sandbox** (in This Mac or Settings → This Mac): **None**, the default, where starting it asks for the same consent as `--unsafe-no-sandbox`, or **macOS sandbox**, macOS's own [experimental sandbox](hosts.md#experimental-sandboxes-on-macos-and-windows), as `--experimental-sandbox`, which falls back to the same consent while its prerequisites are missing. Setting up is in This Mac too: it signs Pi in to your provider (Pi comes with the app; nothing else to install), shows what each sandbox still needs with the command that installs it, and installs what it can once you confirm, such as Apple's developer tools. **Pikibun on this computer** (in Settings → This Mac) runs Pikibun itself on the Mac instead of using a server, for you alone or shared with others (see [Running Pikibun on your own computer](local.md)).
- **Windows** (the same app, x64, on Windows 10 or 11): the same windows and settings, with **This Computer** for This Mac, and each server's host chooses where its sessions run (**Sandbox**, in This Computer or Settings → This Computer): in **WSL2**, the default, where the app runs the connector inside a WSL2 distribution and its sessions get the bubblewrap sandbox, with that distribution's Node.js 24, Pi configuration and pairing, as `pikibun connect` run there; or **natively**, in Windows' own [experimental sandbox](hosts.md#experimental-sandboxes-on-macos-and-windows), or without one after the same consent as `--unsafe-no-sandbox` while it isn't ready. The two keep separate pairings, and different servers can use different ones. See [the app's README](../apps/desktop/README.md#windows).

All of them, and the web app, can [notify you](notifications.md) when a session waits for an approval, finishes or fails: turn it on under **Settings → Notifications** on each device.

The iPhone and iPad app signs in with GitHub through the server's GitHub OAuth app; nothing else needs configuring. It doesn't offer username and password sign-in yet. Each of its sign-ins lasts 30 days and appears under **Settings → Profile → Signed-in apps**, where you can sign it out. The Mac app shows the server's own sign-in page, so it signs in as a browser does: with GitHub or, where the server allows it, a username and password, for 7 days. Neither app opens invite links (the Mac app sends links to your default browser): where `SIGNUP=invite`, a new person creates their account through the link in a browser, then signs in on the app.
