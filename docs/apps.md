# iPhone, iPad, Mac and Windows apps

Pikibun's apps are the Native Shell client ([`apps/nsh`](../apps/nsh/README.md)), the same client the web serves, packaged for each platform by `app-v` releases: a Windows installer and portable zip (x64), the macOS app (Apple silicon), Linux (x86_64), Android, and iOS through TestFlight. They are previews: each `app-v` release is a GitHub prerelease. The earlier Electron Mac and Windows app is removed; its last `desktop-v` release was its last.

New to the Mac, Windows or Linux app? The [desktop app user guide](desktop/README.md) walks through its three modes: a [client](desktop/client.md) of a Pikibun server, a [host](desktop/host.md) that also runs sessions on your computer, or [self host](desktop/self-host.md) with all of Pikibun on your computer.

- **Every platform** has the web client's pages: sign-in, the sidebar and Sessions, a new session, a session with its panel, share and invite links, and Settings. The native builds sign in only with a [code](accounts.md#signing-in-an-app-with-a-code) made where you are signed in already, on the web or in another app (its QR code for a phone's camera, or its link), and ask for no server address, since the link names its server; each such sign-in is listed under **Settings → Profile → Signed-in apps**. GitHub and passwords sign in on the web, where accounts are made too.
- **This Mac** (This Computer on Windows and Linux), under **Settings**, makes the computer one of your hosts for the server you're signed in to: it pairs it in one step, starts and stops its host (with the same consent as `--unsafe-no-sandbox` where there is no sandbox; on macOS, **None** or **macOS sandbox**), chooses its models, signs Pi in to a provider, and lists what the computer lacks with how to get it. The app runs the `pikibun` command for it (from npm: when it's missing or too old, the page's **Install pikibun** button installs it into the app's own folder with your Node.js, with no sudo or PATH change; after an update of the app, its first start updates that copy from npm before the host starts; a `pikibun` installed with `npm install -g` runs where the app has none, and is yours to update), with `pikibun connect`'s state, so a computer paired from a terminal carries over, and only one of the two runs at a time. Hosting lasts while the app is open. See [This Computer](../apps/nsh/README.md#this-computer).
- **Self host** is where a fresh install starts: at its first launch the app runs Pikibun on the computer and signs in to it, with **Sign in to another server** as the other choice, and the sidebar's server button switches between the servers the app is signed in to. Under **Settings** (and **Run Pikibun on this Mac** on the sign-in screen), it runs Pikibun itself on the computer, as `pikibun serve` does: for you alone at `http://127.0.0.1:7878`, with the computer as its host. It needs no GitHub OAuth app or other account: it asks the same consent as This Mac where there is no sandbox, and signs the app in to it as its owner with the server's own sign-in token. It runs `pikibun serve --stdio` with `pikibun serve`'s state, so a Pikibun set up in a terminal carries over. It runs while the app is open and starts again at the next launch if it was running. See [Self host](desktop/self-host.md) and [its design](../apps/nsh/README.md#self-host).
- **Files**: the desktop builds attach any file dropped on the chat box or pasted from a file manager; iPhone and Android pick photos.
- **Updates**: the macOS, Windows and Linux builds check GitHub for a newer `app-v` release at launch and every six hours (a prerelease only while they run one), and offer it on the main page (above the chat box that starts a session, or above the session list in a narrow window; **Later** puts it off until the next launch) and under **Settings → Profile → This app**, which also checks on demand. **Update** downloads the release's package for the computer with a progress bar, through the proxy the computer's own tools use where there is one (Windows' or GNOME's proxy settings, or the `https_proxy`, `all_proxy` or `http_proxy` your login shell exports), checks it against the SHA-256 GitHub publishes and against the signature Pikibun's release key made for it (a release without one is offered as its page instead, and a package whose signature doesn't match is deleted, not installed), installs it and restarts Pikibun: on Windows its installer runs silently and starts Pikibun again; on macOS and Linux the app replaces its own app bundle or folder, which needs write access to the folder it is in (where it has none, it says so and offers the release page). Where a release has no package for the computer (a Mac on Intel), the release page is offered. The updated app then updates its own copy of the `pikibun` command, which This Mac and Self host run. See [Updates](../apps/nsh/README.md#updates).

The web client can [notify you](notifications.md) when a session finishes or fails; the native builds don't show notifications yet, but manage your preferences and devices under **Settings → Notifications**.
